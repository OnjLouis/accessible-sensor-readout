Sensor Readout Server Manual

Version 6.2.0

This small relay lets Sensor Readout computers exchange encrypted remote-monitoring snapshots and changes. It stores and relays opaque encrypted bytes; it does not decrypt or interpret sensor readings.

Requirements

  • A Linux computer using systemd, including a typical Raspberry Pi OS installation.
  • Python 3.8 or later. No third-party Python packages are required.
  • A trusted local network or VPN, or an existing HTTPS reverse proxy for Internet access.
  • Administrator access through sudo for the managed service installation.

Guided Installation

Extract the release ZIP, open a terminal in the extracted folder, and optionally verify the package before installing it. The installer verifies the package again before it changes the system.

python3 sensor_readout_server_control.py verify .

Start the guided installer with this complete command:

sudo python3 sensor_readout_server_control.py install

The installer asks numbered questions and offers safe defaults. Press Enter to accept a displayed default. It will ask:

  1. Whether clients connect through a private LAN or VPN, or through an existing HTTPS reverse proxy.
  2. Which listening port to use. The default is 48673.
  3. For a private network, which detected address other computers should use. You may instead enter a DNS name, local-network address, private-network address, or VPN address.
  4. For HTTPS, the complete HTTPS address already provided by your reverse proxy.
  5. Whether to proceed after showing an exact summary.

The installer creates a dedicated unprivileged sensor-readout service account, preserves the access token and data during later updates, installs versioned files below /opt/sensor-readout-server/releases, activates the current link atomically, installs a hardened systemd service, and checks the running version. If the service fails its health check, the previous release and configuration are restored.

After a successful guided installation, the installer writes an owner-only sensor-readout-connection.srconnection file in the terminal's current folder. If that name already exists, it chooses a numbered name instead of overwriting it. When run through sudo, the file is returned to the user who started the installer.

The installer does not expose the server for you

It does not change a firewall, router, VPN, DNS record, reverse proxy, or TLS certificate. Plain HTTP is suitable only on a trusted local network or a protected private network such as a VPN. Use HTTPS before exposing the relay to the public Internet.

After Installation And Setup

Import the generated .srconnection file from Options > Remote computers in Sensor Readout. Enter the same monitoring password locally on every participating Sensor Readout computer. The monitoring password is separate from the server access token and is never stored in the connection file.

sudo sensor-readout-server-control status
sudo sensor-readout-server-control health
sudo sensor-readout-server-control connection ./sensor-readout-connection.srconnection

The connection-file command is useful when the original file is unavailable. Protect the result like a password because it contains the relay access token.

Run the guided setup again whenever the listening address, port, reachable client address, request timeout, inactive-computer retention, automatic-update choice, or server access token needs to change. It shows the current values, summarizes the proposed changes, restarts the service, verifies its health, and restores the previous settings if the new configuration fails.

sudo sensor-readout-server-control setup

The relay never receives or stores the monitoring password, so the setup command cannot change it. Change that password in Sensor Readout on the participating Windows computers. Regenerating the separate server access token invalidates existing .srconnection files and writes a replacement connection file for redistribution.

Updates And Rollback

Managed installations enable a daily automatic update check by default. It reads only stable server-vX.Y.Z releases, downloads only the exact SensorReadout-Server-X.Y.Z.zip asset over HTTPS, verifies GitHub's SHA-256 digest and the package's own manifest, then uses the same health-checked deployment and rollback path as an offline update. Ordinary Windows Sensor Readout releases and archives are explicitly ignored.

sudo sensor-readout-server-control check-update
sudo sensor-readout-server-control update-online

For an offline server, extract a newer server archive to a new folder, open a terminal there, and use the existing verified package path:

sudo sensor-readout-server-control update .

Every update re-verifies the exact file allow-list, version, and SHA-256 hash of every packaged file. The newest three releases are retained for rollback.

sudo sensor-readout-server-control rollback

Unattended Installation

The guided installer runs only when its package folder is omitted and a controlling terminal is present. Redirected or unattended execution never waits at a prompt. Automation can supply the package folder and all settings explicitly.

Syntax example: do not copy unchanged

The uppercase words below are values that an administrator must replace. The reserved .invalid domain is used in explanatory examples precisely because it is not a real server.

sudo python3 sensor_readout_server_control.py install PACKAGE_FOLDER --host LISTEN_ADDRESS --port PORT --public-url PUBLIC_URL --non-interactive

Security And Privacy

  • The access token authenticates requests to the relay. Treat the settings and .srconnection files as credentials.
  • The separate monitoring password never reaches the relay. Sensor Readout uses it locally to select a private monitoring space and derive encryption and authentication keys.
  • Every publishing computer keeps a private random write credential. The relay records only its hash and rejects attempts to replace that computer's data, consume its commands, or remove its entry without the credential.
  • Anyone with both the connection file and monitoring password can read computers in that monitoring space and request advertised fan profiles. Share both only with authorized people.
  • The relay can see request times, client network addresses, opaque random identifiers, revisions, and encrypted payload sizes. It cannot read computer names or sensor rows.
  • Rotate AuthToken and redistribute a new connection file if it is disclosed.
  • Logs rotate automatically and omit monitoring passwords, readable sensor data, and complete opaque identifiers. Routine successful updates and heartbeats are not written at normal log level.

Storage Endurance

The relay persists an encrypted checkpoint for each computer so it remains available while offline and after a relay restart. Normal live differences are bounded in RAM. The publishing client periodically replaces the checkpoint, and a sequence mismatch after an abrupt restart causes an automatic complete resynchronization. The default activity timestamp is written at most once per hour. This avoids thousands of small daily files and is suitable for Raspberry Pi microSD storage; retained data is not a historical sensor database.

Manual Service Setup

The verified guided installer is the normal workflow. Advanced administrators may use sensor-readout-server.service.example and sensor-readout-server-systemd-settings.example.json as starting points for a manually managed service. Replace every placeholder, preserve owner-only credentials, run the relay as an unprivileged account, and use the control script's verify command before copying files.

Run python3 sensor_readout_server.py --help and python3 sensor_readout_server_control.py --help for the complete command-line reference.
